# 上线速查（零成本路线，一页纸）

目标：不买域名、不备案，让你们在国内不靠梯子也能打开。原理见 [deploy-cn.md](deploy-cn.md)「路线 Z」：
应用跑在免费托管上，**自己转发** Supabase（免费数据库域名在国内全部不通，托管域名可以）。

## 你要做的五步

- [ ] **1. 推代码到 GitHub**
  ```bash
  # 先在 GitHub 网页建一个空仓库（不要勾 README / .gitignore）
  bash dev/push-to-github.sh https://github.com/<你的用户名>/<仓库名>.git
  ```

- [ ] **2. Render 建服务**
  https://dashboard.render.com → **New → Blueprint** → 选中刚推的仓库。
  根目录 `render.yaml` 会告诉它怎么建（一个免费实例，同时跑应用 + 转发）。
  若创建时报错说不支持 `singapore` 区域，删掉 `render.yaml` 里 `region: singapore` 那一行，
  用默认区域再建（注意：区域创建后不可修改，只能删掉重建）。

- [ ] **3. 在控制台补两个值**
  | 变量 | 填什么 |
  | --- | --- |
  | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase 项目的 anon key |
  | `SUPABASE_UPSTREAM_URL` | `https://<你的项目>.supabase.co` |

  另外确认服务名：如果不是 `ai-de-xiao-wu`，把 `render.yaml` 里**两处** `.../supabase`
  的域名改成 `https://<你的服务名>.onrender.com/supabase`（域名由服务名决定，必须与之一致）。

- [ ] **4. 生产库跑迁移**（按顺序，缺一个都会出问题）
  `202608130001_initial_schema.sql` → `202608140001_fix_letter_notification_trigger.sql`
  → `202608150001_letter_reply.sql`（**最后这个不跑，回信功能写入会失败**）

- [ ] **5. 验收**
  ```bash
  node dev/verify-deployed.mjs https://<你的服务名>.onrender.com
  # 想连登录后的页面一起查：
  E2E_USER_EMAIL=你的邮箱 E2E_USER_PASSWORD=密码 node dev/verify-deployed.mjs https://<你的服务名>.onrender.com
  ```
  它会检查登录页、未登录拦截、转发器守门，带账号时再逐页确认。
  **把输出贴给我**，红的我去修。

## 会碰到什么

- 闲置 15 分钟后休眠，**再打开约 1 分钟**——这期间 Render 会显示它自己的加载页，不是白屏。
- 用不着保活也能用；想要"随时秒开"就把 `.github/workflows/keep-alive.yml` 留着
  （它只在北京时间 07:00–24:00 每 10 分钟 ping 一次，约 540 小时/月，免费额度 750）。
- 每月 750 小时是整个工作区共享，**超了会把该工作区所有免费服务停到月底**，所以别再开第二个。

## 出问题先看这里

| 现象 | 多半是 |
| --- | --- |
| 一直跳回登录页 | `SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_URL` 与真实域名不一致 |
| 页面能开但读不到数据 | `SUPABASE_UPSTREAM_URL` 或 anon key 没填对 |
| 保存/回信报 `reply_to_id` 不存在 | 第 4 步的第三个迁移没跑 |
| 构建失败 | `render.yaml` 的构建命令已有 npm 兜底；把构建日志贴给我 |

更详细的说明、实测数据与故障表在 [deploy-cn.md](deploy-cn.md)。
